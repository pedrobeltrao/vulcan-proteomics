## 1. What we should stop doing

1. **Designing a null-set gate first and checking its feasibility afterwards (the main time sink since M1).** After the A1 gate failure (D12) the project spent roughly D12 to D32 (about 20 decisions, ~59 of 173 commits mention an amendment/A-number) on getting a passable null set, and T1 is still unlooked:
   - A2/DN2 was adopted, implemented, tagged and walked before anyone knew the pool size; it ended "not evaluable" (D24, 23942fa): 6 of 10 projects, |A| 24,581 vs 120k needed. A first walk was also wasted on a query bug (D16, 2650cb8).
   - DNIT (IT-CID nulls) ran a whole walk and was declared futile (D20, 96cf5e2): 581 usable spectra vs 120k.
   - A3's power check said v2_sep tiers are "expected not evaluable" only after adoption (D22 then D23, 610de34 vs 195013f).
   - A4 went through rev 0 to rev 3 with two independent reviews (d42062c, d0b3f94, 138f102, a158cf8; reviews/amendment_A4_review*.md) and was then not run because simulated P(v1 minimum) was 0.08-0.43 (D28, 3a71356). Only then did the cheap label-free C9 simulation, proposed by a reviewer, give 0.97-1.0 (D30).
   Rule: run the label-free yield/power simulation and write the go/no-go threshold *before* drafting the amendment, not after adoption; the simulation is cheap (hours), the amendment+review+walk was days.
2. **Amendment drafts that reach review with blocking defects.** Every amendment review returned "do not adopt as written" or "adopt with changes" with blocking items: A3 (items 4-5 preconditions), A4 rev 0 (3 blocking), rev 2 (2 blocking), A5 (2 blocking), A6 (B1-B3). Five review rounds on A3-A6 is a pattern, not bad luck. Stop having the author's own agent re-derive statistics in a new module each time (a4_power, a4_r1_walk, a6_stats...); the A6 reviewer had to demand a test that a6_stats reproduce a4_power to 1e-12. Reuse one frozen power/verdict library with a regression test and have the reviewer run a checklist (cross-amendment consistency, arm lists, who may read what) generated from the previous reviews.
3. **Comparing to a weak or unfair comparator and leading with it.** D17: the +2.8% ID gain over Sage vanished against the strongest comparator (0.990x). D21 headlined 1.22x vs Sage+pred+mokapot with a non-chimeric comparator; the fair chimeric comparator (D25, E7b) gave 1.15x and 0.999x at protein level. The M1 retro already flagged the status-summary lead; it is still the 2026-10-27 text with "+2.8% IDs", "40-65x" and "A2 being implemented" while D24, D25 and D28-D32 have since changed the picture. Stop writing speed/ID headlines before the strongest, fairly configured comparator exists, and stop letting the status block go a day stale.
4. **Timing and freeze under deadline pressure with weakening checks.** The bench lock is still the timing protocol (D31.4, "timings are taken under the bench lock") although retro M1 item 1 asked to replace it and M6 lost its bench to a 2 h lock hold; no exclusive-slot change is recorded. D31 replaced the "separate quiet-node headline session" with "existing locked measurements"; D32 replaced D0's 3 h freeze dry run by byte-identity evidence from an earlier candidate and a "later diffs are opt-in" argument, and accepted a comparator-equality tolerance for non-deterministic Sage. These are disclosed, but each is a weakening made by the time limit. Stop planning final freezes that need more node time than remains; reserve the freeze budget first and cut features instead.
5. **Committing results before the code that produced them.** Two "git_sha -> commit containing all code" fixups (7fc78f7, 0165732) and a later "M7: git_sha" fixup (7bad342), A2 gate code unversioned at M1 time, and E7b's cohort_runs.jsonl and M6 logs still untracked at the start of this review. Stop: a results commit must be made from a clean tree at the commit named in git_sha (the D16 "run from clean worktree" practice, 5c90498, is the model).
6. **Node-local /tmp for bulk state.** After lesson 8 was written, A2 DN2 hit ENOSPC on /tmp (note 20, 2c734fa) and E7b's two 192-run cohorts filled /tmp and killed both comparator runs (7865f8e, the disk lesson). A free-space guard and a persistent cache path should be the default launcher, not a lesson.
7. **Unbounded RESEARCH_TREE.md.** It is ~60 KB; D-entries run to 10+ nested lines (D32, D31, D30). D0 and D2 ("only 4 cores") are still shown as active though D5 superseded them (M1 retro item 8 not done). Stop appending prose to decisions: one headline line per decision, details in the linked review/results file, superseded decisions marked `[-]` and moved below.
8. **Duplicate and exploratory work with no stop rule.** Examples: two M1e baseline passes (M1 retro), DNIT's walk repeated "once from the start" (cff5eb1), v2 encoder arms E5/E6 built and trained before a cheap kill test and then both NO-GO (D19, 46d7612), C9-style simulation not done until D28. Give each side track a stated kill criterion and time box in its first commit.

## 2. What worked well (keep)

1. **Independent review gated every sealed-adjacent decision and caught real defects.** Review before adoption stopped invalid designs five times (A3, A4 x2, A5, A6) and the D28 review redirected the project from a 3-4 day, 0.75-1.9 TB A4 run to the C9 human removed-peptide simulation that actually gave a feasible null (D28 to D30, 2f8d5c4, 3097ef5). No sealed set has been opened and SEALED_LEDGER remains closed.
2. **Label-free decisions dated before data, and failures recorded as final.** D12 (A1 failures stand), D16 (bug fixed and re-walk once, same seed, no spectra seen), D24 (DN2 "not evaluable, final under P4"), D20 (DNIT futile, spent), A4 not run on label-free power (D28). Training/selection rules were committed before download or training (90b64d8, 8f687e0, 0b7dfdb, 6607ecd, 0d9d795). This is why negative outcomes were cheap to accept.
3. **Honest correction of our own headline.** D17 (gain is predicted features), D25 (1.22 to 1.15, no protein gain, Sage chimera miscalibrated by rank so ratios favour the comparator), D19 (encoders NO-GO by pre-stated rules), D10 (homo-family XL pairs reported as uncontrolled, not dropped), D18 (reported-only secondary arm C).
4. **Exactness before speed, and opt-in merges.** E11 GPU MS1 finder bitwise-equal on 13 dev runs and merged only after the freeze rehearsal, default cpu (D27, 996f478, cec4f37); scoring speed 7.2x with bit-identical features and ID sets (ed98d7c); E7b fast paths bitwise on D0/D1 (D25). Speedups never required re-deciding a claim.
5. **Pinned, content-addressed predictor store** after G0 failed on TMT (b574398, 4d75553, D20): fixed a non-determinism that would have voided every label-swap test.
6. **Freeze rehearsal before the final freeze** (3753787, e0b94aa): found a real shared-cache bug (e0b94aa: AlphaPeptDeep not batch-invariant shifted features) and proved v1 artefacts byte-identical to prereg-v0.4.2 on D1/D0 with a closure guard that fails at HEAD, so unintended drift is detectable.
7. **Role separation**: one agent for selection/admission, another for the single gate run (D15 per A2.9.5; D31.3), T1-blind authors for A6, and sealed-derived intermediates deleted (D29.5). Also the PI input at D26/D28 was reviewed rather than executed (pi_proposal_D28_review.md).
8. **Time-boxing under a hard external limit.** D31 re-cut the plan to the 10 h node budget with explicit dropped items (DIA, XL/LiP/CF follow-ups) and an outcome-independent rationale for shortening the A5 box.
